# Word 97 large-document startup on M1 Pro

The downloaded binary DOC is 4,807,680 bytes (4.59 MiB), ten pages, with text and images. Word 97 opens it successfully. Source ZIP: https://images.sampletemplates.com/wp-content/uploads/2021/06/Entrepreneur-Training-Needs-Assessment-Report.zip (member `tna_report_engro_project_1.doc`). SHA-256: `111edaf8471ba04a50c770fc5c5366b82013ec14558bc670633402c2b6fe5f7f`.

The existing local Windows 95 disk was reused with a private compressed QCOW2 child. The document was staged as `C:\BENCH5M.DOC`; full FAT readback matched the download. A checkpoint before launching Word is at `build/snapshots/word5m-launch`. Each headless run restores independently and discards its private disk delta. The timed action is Enter in the prepared Run dialog, ending when the first-page cover title at rectangle [290,289,510,308] exactly matches reference pixels. It does not measure reading/rendering every page. Restore is excluded. Guest file cache is from the checkpoint; host file cache is warm. The document and guest disks remain ignored local artifacts.

Three unprofiled runs per executable, baseline first then linked (not interleaved):

| Build | Median wall response | Median process CPU |
| --- | ---: | ---: |
| Original baseline 57ce863 | 2127.6 ms | 2052.9 ms |
| Experimental out-of-line direct links, warmup 256 | 2187.3 ms | 2131.0 ms |

All six runs reached the expected pixels and exited cleanly. Approximately 100 million guest instructions execute, versus approximately 31 million for blank Word startup. Linked runs make approximately 5.3 million direct transitions, but median process CPU is 3.8% higher in this preliminary grouped comparison. This is not evidence of a speedup. Harness capture/control work is included in both timings. Executable hashes and individual samples are preserved in the adjacent JSON; the candidate is experimental and not an accepted performance improvement.

Reproduce with `python3 tools/bench_snapshot_task.py build/snapshots/word5m-launch --task docs/measurements/word5m-m1-2026-10-26.task.json --repeat 3 --emulator build/direct-links-baseline/pcemu --restore-timeout 30 --output build/word5m-recheck`. For the experimental executable add `--jit-direct-links --jit-link-warmup 256` and change executable/output paths.

## Rotating comparison and profile

A follow-up comparison runs five rounds sequentially, rotating the order of
baseline, candidate links off, warmup 256 and warmup 1024. Median process CPU
is respectively 2141.0, 2165.6, 2266.2 and 2202.9 ms. Thus warmup 256 is 5.8%
slower than baseline and warmup 1024 is 2.9% slower. No runs were discarded.
The per-round data and executable hashes are in
[word5m-m1-paired-2026-10-26.json](word5m-m1-paired-2026-10-26.json).

A separate Instruments recording with JIT maps produced 2337 main-thread
samples inside the verified task window: interpreter 28.5%, JIT dispatch/cache
validation 24.4%, generated code/helpers 17.2%, compilation 11.3%, capture/video
9.6%, device polling/interrupts 6.2%. Direct-link checks themselves were 17
samples (0.73% of main-thread samples). These are sampled shares, not isolated
function durations; the instrumented run is excluded from speed comparisons.
Raw trace and JIT map remain local under
`build/word-large-doc/instruments-linked/run-0/`.
